# Unreal Engine Codex 작업 규칙

## 분석 범위

- 기본적으로 Source/, Config/, Plugins/의 필요한 소스만 분석한다.
- Intermediate/, Saved/, Binaries/, DerivedDataCache/, .vs/는 검색하지 않는다.
- Content/의 바이너리 에셋은 필요한 경우에만 확인한다.
- 엔진 설치 폴더 전체를 탐색하지 않는다.

## 토큰 절약

- 프로젝트 전체 탐색을 반복하지 않는다.
- 수정할 파일을 먼저 특정하고 필요한 부분만 읽는다.
- 로그는 오류 메시지와 주변 20줄만 출력한다.
- 빌드 성공 시 전체 로그를 출력하지 않는다.
- 동일한 오류에 대한 무의미한 재시도를 방지한다.
- 작업 결과는 변경 파일과 검증 결과 위주로 짧게 보고한다.

## 작업 방식

- 기존 코드를 최대한 유지한다.
- 필요한 기능만 수정한다.
- 전체 프로젝트 리팩터링은 명시적 요청이 있을 때만 진행한다.
- 빌드는 필요한 경우에만 수행한다.

## 사용자 지정 변경 범위와 기능 분리 규칙

- 현재 사용자 프롬프트에 명시된 기능과 그 기능 통합에 직접 필요한 연결 코드만 변경한다.
- 요청하지 않은 다른 기능, 게임 규칙, 밸런스, 맵, 에셋, UI 동작을 변경하려면 변경 대상과 이유를 사용자에게 먼저 설명하고 명시적인 답변을 받은 뒤 수행한다. 무응답은 동의가 아니다.
- 기존 기록의 미완료 기능이나 개선 제안은 신규 구현의 허가로 해석하지 않는다.
- 파일을 수정하기 전에 해당 파일의 역할과 수정 범위를 특정한다. 파일의 담당 역할 밖의 로직은 추가하거나 변경하지 않는다.
- 소스는 기능별 폴더로 구분하고, 각 기능 안에서 Public(계약/타입/공개 인터페이스)과 Private(구현)의 역할을 구분한다.
- UI는 표시와 입력 전달을 담당하고, 게임 규칙과 저장 처리는 각각 해당 기능에서 담당한다. 기능 간 통신은 명시적인 인터페이스, 데이터 전달 또는 이벤트를 통해 수행한다.
- 기능 내부 구현을 다른 기능이 직접 변경하거나 서로의 내부 상태를 임의로 쓰지 않도록 한다. 공용 계약 변경은 영향받는 호출부를 확인하고 요청 범위를 넘어가면 먼저 질문한다.
- 언리얼 클래스/에셋 이동은 리플렉션 이름과 기존 참조를 유지한다. Content 에셋의 파일 탐색기 이동/이름 변경으로 참조를 깨뜨리지 않는다.
- 독립성은 의존성 경계와 관련 검증으로 확인한다. 다른 기능에 절대 영향이 없다고 보장하지 않는다.

## 재시도와 토큰 비용 제한

- 같은 오류/동일 목적의 실패한 명령 실행은 최초 시도를 포함하여 최대 2회로 제한한다. 두 번째 실행 전에 원인과 변경점을 확인한다.
- 두 번 실패하면 같은 명령이나 표현만 바꾼 동등한 요청을 반복하지 않고, 오류 원인·영향·필요한 사용자 입력을 간단히 보고한다. 별도의 비용 발생 작업이나 광범위한 수정으로 우회하지 않는다.
- 분석은 파일 목록을 먼저 확인한 뒤 관련 파일/함수만 읽고, 생성 폴더와 긴 로그의 반복 출력을 피한다.
- 검증은 변경 기능과 연결 지점에 필요한 빌드/기존 테스트를 우선한다. 통과한 검증은 새 변경이나 새로운 근거 없이 반복하지 않는다.
